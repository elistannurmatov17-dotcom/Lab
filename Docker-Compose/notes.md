* `docker compose up -d` — запустить сервисы из файла `compose.yaml` в фоновом режиме (демоном).
* `docker compose ps` — показать статус запущенных контейнеров текущего проекта.
* `docker compose logs -f [имя_сервиса]` — смотреть логи контейнера в реальном времени (`-f` означает follow/следовать). Выход из логов — `Ctrl + C`.
* `docker compose stop` — остановить контейнеры (данные в volumes сохранятся).
* `docker compose down` — полностью остановить и удалить контейнеры этого проекта.
* `docker stats` — показать, сколько оперативной памяти (RAM) и процессора (CPU) едят контейнеры прямо сейчас.



## 📦 Полный гайд по Постоянным данным (Volumes & Bind Mounts)

Контейнеры по умолчанию **эфемерны** (непостоянны). Всё, что создано внутри контейнера во время его работы, полностью удаляется вместе с контейнером при команде `docker compose down`. Чтобы данные жили вечно, Docker предлагает два главных механизма: **Bind Mounts** и **Volumes**.

---

### 1. Bind Mounts (Монтирование локальной папки)
Ты связываешь конкретную папку на своем реальном сервере (Ubuntu) с папкой внутри контейнера.

* **Синтаксис в compose.yaml:**
  ```yaml
  volumes:
    - ./html:/usr/share/nginx/html
  ```
* **Как это работает (Логика):**
  * `[Слева от двоеточия]` — Точный путь на хосте (на твоей Ubuntu). Точка `./` означает текущую папку, где лежит compose-файл.
  * `[Справа от двоеточия]` — Точный путь внутри контейнера, куда "подкладывается" папка хоста.
* **Главная особенность:** Если папка на хосте пустая, она **затрет** (скроет) все файлы, которые изначально были внутри контейнера по этому пути.
* **Для чего используется:** Идеально подходит для разработки сайтов, конфигов (`nginx.conf`) или исходного кода. Ты меняешь файл на Ubuntu в nano/VS Code — изменения мгновенно видны на сайте в контейнере.

---

### 2. Named Volumes (Именованные тома Docker)
Ты не указываешь конкретный путь на Ubuntu. Ты просто придумываешь имя для "виртуальной флешки", а Docker сам создает её в своих системных недрах и управляет ей.

* **Синтаксис в compose.yaml:**
  ```yaml
  services:
    db:
      image: postgres:alpine
      volumes:
        - my_db_data:/var/lib/postgresql/data # Привязываем том к сервису

  volumes: # ОБЯЗАТЕЛЬНО объявляем том в самом низу файла!
    my_db_data:
  ```
* **Как это работает (Логика):**
  * Docker физически создает изолированную папку на сервере по адресу `/var/lib/docker/volumes/my_db_data/_data`. Обычному пользователю туда лазить не нужно.
* **Главная особенность:** При первом запуске, если твой Named Volume пустой, а внутри контейнера по этому пути уже лежат файлы (например, стартовая база данных), Docker **автоматически скопирует** эти файлы внутрь твоего тома. Ничего не затрется!
* **Для чего используется:** Идеально для баз данных (PostgreSQL, MySQL), логов и любых системных данных, которые генерирует само приложение и в которые человеку не нужно лезть руками.

---

### ⚖️ Главные отличия: Что и когда выбирать?

| Критерий | Bind Mounts (`./папка:путь`) | Named Volumes (`имя:путь`) |
| :--- | :--- | :--- |
| **Где лежат файлы?** | Там, где ты указал (например, в твоей лабе). | В системной папке Docker (`/var/lib/docker/...`). |
| **Что будет, если папка пуста?** | Очистит папку внутри контейнера. | Скопирует начальные файлы из контейнера в том. |
| **Удобство для человека** | Высокое (легко править файлы через nano). | Низкое (сложно добраться до файлов руками). |
| **Безопасность и скорость** | Зависит от прав на папки в Linux. | Максимальная (Docker сам оптимизирует скорость). |
| **Для чего лучше?** | Сайты, скрипты, конфигурационные файлы. | Базы данных (Postgres, Redis), загрузки пользователей. |

---

### 🛠️ Полезные команды админа для работы с Volumes
Поскольку Named Volumes скрыты от глаз, управлять ими нужно через специальные команды:

* `docker volume ls` — показать список всех именованных томов в системе.
* `docker volume inspect [имя_тома]` — показать подробную информацию о томе (в строке `Mountpoint` будет виден реальный путь к файлам на Ubuntu).
* `docker volume rm [имя_тома]` — удалить том (работает только если контейнер, использующий его, остановлен). **Внимание: данные удалятся навсегда!**
* `docker volume prune` — очистить все неиспользуемые (оставшиеся от старых контейнеров) тома. Полезно, если на диске заканчивается место.

## 🧹 Обслуживание Docker и Генеральная уборка (Спасение диска)

Когда на сервере заканчивается место (раздел `/` забит на 95-99% по команде `df -h`), Docker-контейнеры начинают падать. Для очистки системы используются следующие команды:

### 1. Полная очистка Docker (Главная команда админа)
```bash
sudo docker system prune -a --volumes
```
* **Как это работает (Логика):**
  * `prune` — запускает процесс удаления неиспользуемых ресурсов.
  * `-a` (all) — удаляет вообще все скачанные образы (Images), которые прямо сейчас не привязаны ни к одному запущенному контейнеру. Освобождает гигабайты места.
  * `--volumes` — одновременно находит и уничтожает все заброшенные анонимные тома-пустышки, которые остались от старых тестов.

### 2. Очистка кэша пакетов Ubuntu
```bash
sudo apt clean
```
* **Логика:** Удаляет из системы все скачанные ранее установочные файлы `.deb`. Программы остаются установленными, но их архивные копии больше не занимают место.

### 3. Удаление конкретного забагованного тома
```bash
sudo docker volume rm [имя_тома]
```
* **Логика:** Используется, если база данных выдает ошибку совместимости версий в логах. Контейнер нужно остановить (`down`), удалить сломанный том этой командой, а затем запустить стек заново (`up -d`) — Docker создаст том чистым и с правильной конфигурацией.

### 📊 Полезные утилиты проверки ресурсов:
* `df -h` — показывает список жестких дисков. В графе **Use%** для раздела `/` не должно быть 100%.
* `free -h` — показывает состояние оперативной памяти (RAM) и файла подкачки (Swap).


## 🧠 Житейская мудрость админа (Лайфхаки и грабли)

* **Имена файлов:** Называй файлы строго `compose.yaml`. Тогда Docker поймет команду `docker compose up -d` без лишних флагов `-f`.
* **Контейнерная сеть:** Имя сервиса в файле (например, `my-database`) становится его сетевым именем (доменом) внутри Docker. Контейнеры общаются друг с другом по именам, а не по IP.
* **Ошибка занятого порта:** Если видишь `port is already allocated`, значит, порт на Ubuntu занят. Меняй левую цифру в `ports` (например, с `"8080:80"` на `"8081:80"`).
* **Регистр в Linux:** Папки `lab` и `Lab` — это разные папки. Будь внимателен к регистру букв.
* **Пробелы:** Не создавай папки с пробелами через `mkdir`. Используй дефис: `Docker-Compose`.
