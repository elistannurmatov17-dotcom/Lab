
## 🖥️ Полный гайд по работе в веб-интерфейсе VMware ESXi

Интерфейс VMware Host Client логичен, но требует строгого соблюдения последовательности действий: Сеть -> Хранилище -> Виртуальная машина.

### 🌐 1. Настройка Сети и Портов (Networking)
В отличие от Proxmox, где используется простой Bridge, в VMware сеть делится на виртуальные коммутаторы (**vSwitch**) и группы портов (**Port Groups**).

* **vSwitch0 (Виртуальный коммутатор):** Создается автоматически. Он связывает физическую сетевую карту твоего сервера с виртуальной средой.
* **Management Network (Группа портов):** Через нее ты заходишь в сам веб-интерфейс ESXi. Трогать её настройки безопасности нельзя, иначе потеряешь доступ к серверу.
* **VM Network (Группа портов для машин):** Это дефолтная сеть для твоих будущих VM.  
* *Админская фишка:* Если тебе нужно изолировать машины (сделать аналог VLAN), зайди в **Networking -> Port groups -> Add port group**, назови её (например, `Isolated-VLAN10`) и в поле **VLAN ID** укажи нужный тег. Все машины в этой группе будут изолированы от основной сети.



### 💾 2. Загрузка образов в Хранилище (Datastore)
Перед созданием машин нужно загрузить ISO-образы операционных систем на сервер.
1. Перейди во вкладку **Storage** (Хранилища) -> выбери твой **datastore1**.
2. Нажми кнопку **Datastore Browser** (Браузер хранилища).
3. Создай отдельную папку `ISO` (кнопка *Create directory*), чтобы поддерживать порядок.
4. Зайди в папку `ISO`, нажми **Upload** (Загрузить) и выбери файл (например, образ Ubuntu или Debian) на своем компьютере Windows. Дождись окончания загрузки на 100%.



### 📦 3. Создание Виртуальной Машины (VM)
1. Перейди во вкладку **Virtual Machines** -> нажми **Create / Register VM**.
2. Выбери **Create a new virtual machine** (Создать новую VM).
3. **Select a name and guest OS:** Задай имя и обязательно выбери правильный тип ОС (например, *OS Family: Linux*, *Version: Ubuntu Linux 64-bit*). Это важно, так как VMware автоматически подберет оптимальные виртуальные драйверы под эту систему.
4. **Select storage:** Выбери твой `datastore1`.
5. **Customize settings (Тонкая настройка «железа»):**
   * **CPU:** Выдели ядра. Разверни вкладку CPU и убедись, что включена функция **Hardware virtualization** (если планируешь запускать внутри Docker).
   * **Memory:** Выдели ОЗУ. Обязательно поставь галочку **Reserve all guest memory (All locked)**, если системе критически важна стабильная скорость без задержек.
   * **Hard disk 1:** Выбери тип диска. *Админская фишка:* Всегда разворачивай настройки диска и выбирай **Disk Provisioning -> Thin** (Тонкий диск). В режиме *Thin* диск будет занимать на физическом сервере ровно столько места, сколько весит сама система внутри (если в виртуалке занято 5 ГБ, то и на сервере отнимется 5 ГБ, даже если ты выделил 100 ГБ). Режимы *Thick* сразу резервируют все 100 ГБ и забивают хранилище пустым местом.
   * **CD/DVD Drive 1:** Переключи в режим **Datastore ISO file**, нажми *Browse* и выбери загруженный ранее образ из папки `ISO`.
   * **Network Adapter 1:** Убедись, что выбрана группа портов `VM Network`.



### 💾 4. Клонирование и Копирование машин (Clone & Copy)
В чистом бесплатном VMware ESXi (без платного центра управления vCenter) кнопка «Clone» заблокирована в веб-интерфейсе. Но админы обходят это ограничение вручную через файлы:

1. Полностью выключи исходную машину (шаблон).
2. Зайди в **Storage -> Datastore Browser -> datastore1**.
3. Создай новую папку для копии (например, `my-new-vm`).
4. Зайди в папку исходной машины, выдели файлы конфигурации **`.vmx`** и виртуального диска **`.vmdk`**, нажми кнопку **Copy** сверху и укажи целевую папку `my-new-vm`.
5. После копирования закрой браузер хранилища, перейди во вкладку **Virtual Machines**, нажми **Create / Register VM** -> выбери **Register an existing virtual machine** (Зарегистрировать существующую VM) и укажи скопированный файл `.vmx`. Машина появится в списке!



### 🛡️ 5. Резервное копирование (Backup)
В бесплатной версии ESXi нет встроенного автоматического бэкапа по кнопке. Для домашних лабораторий и enterprise-серверов используется один из двух стандартов:

1. **Ручной бэкап через Снапшоты (Snapshots):** Перед проведением опасных работ зайди в машину, нажми **Actions -> Snapshot -> Take snapshot**. Система запомнит состояние диска. Если что-то сломалось, нажми *Restore snapshot*. 
   * *Важно:* Снапшоты — это не бэкап! Они сильно тормозят диск, если хранить их неделями. Сделал работу — удали снапшот (Delete snapshot).
2. **Автоматизация через скрипт ghettoVCB (Стандарт индустрии):** Это бесплатный скрипт на Bash, который ставится в планировщик задач (Cron) самого ESXi. Он умеет ночью незаметно выключать машину или делать Snapshot, копировать её файлы на внешний сетевой диск (NFS) и включать обратно.



## 🔄 6. Обновление (Update), Патчи и «Репозитории» в VMware ESXi

В VMware ESXi нет команды `apt` и классических репозиториев. Система обновляется через **Offline Bundles** (zip-архивы с патчами) или напрямую через онлайн-депо VMware с помощью утилиты **`esxcli`**.

### Перед обновлением ОБЯЗАТЕЛЬНО:
1. Переведи хост в режим обслуживания (в веб-интерфейсе: **Actions -> Maintenance mode -> Enter**). Это остановит или перенесет все виртуалки.
2. Включи доступ по SSH (в веб-интерфейсе: **Manage -> Services -> TSM-SSH -> Start**).

### Способ 1: Онлайн-обновление (Аналог репозитория)
Если твой сервер ESXi имеет прямой доступ в интернет, ты можешь обновиться напрямую с официального хранилища патчей VMware.

1. Подключись к ESXi по SSH и разреши файрволу исходящий HTTP-трафик для загрузки обновлений:
   ```bash
   esxcli network firewall ruleset set -e true -r httpClient
   ```
2. Проверь список доступных профилей (онлайн-репозиторий) для твоей версии (например, для ESXi 8.0):
   ```bash
   esxcli software sources profile list -d https://vmware.com | grep -i "ESXi-8"
   ```
3. Запусти установку выбранного профиля обновления:
   ```bash
   esxcli software profile update -d https://vmware.com -p ESXi-8.0U2b-23305546-standard
   ```
4. Верни настройки файрвола обратно и перезагрузи сервер:
   ```bash
   esxcli network firewall ruleset set -e false -r httpClient
   reboot
   ```

### Способ 2: Офлайн-обновление (Если нет интернета на хосте)
1. Скачай патч в формате `.zip` с портала Broadcom.
2. Загрузи его в свой **Datastore Browser** (например, в папку `ISO`).
3. Запусти обновление из SSH, указав точный путь к файлу на диске:
   ```bash
   esxcli software vib update -d /vmfs/volumes/datastore1/ISO/VMware-ESXi-8.0-Patch.zip
   ```



## 🔐 7. Сетевой экран (Firewall) и Правила доступа (Rulebase)

Файрвол в ESXi работает на уровне самого гипервизора (защищает сам хост, а не виртуалки внутри). По умолчанию в системе включена политика **«Запрещено всё, что явно не разрешено»**.

### Настройка правил (Rulebase) в веб-интерфейсе:
Перейди во вкладку **Networking -> Firewall**. Ты увидишь список встроенных правил (Rulesets).

* **Защита веб-панели и SSH:** Найди правила `vSphere Client` (порт 443) и `sshServer` (порт 22). 
* **Фишка ограничения по IP (Allowed IP Addresses):** По умолчанию к твоей админке может подключиться любой компьютер из домашней сети. Чтобы защитить сервер, выдели правило `sshServer`, нажми **Edit settings**, сними галочку *Allow connections from any IP* и жестко пропиши IP-адрес своего рабочего компьютера (например, `192.168.1.5`). Теперь никто другой не сможет даже попытаться подобрать пароль по SSH!

### Управление файрволом через CLI (Командную строку):
* Посмотреть статус всех правил: `esxcli network firewall ruleset list`
* Разрешить конкретный сервис (например, web-клиент): `esxcli network firewall ruleset set -e true -r vSphereClient`
* Заблокировать сервис: `esxcli network firewall ruleset set -e false -r sshServer`



## 💎 8. Профессиональные секреты и Enterprise-фишки ESXi

### 🕒 Фишка №1: Синхронизация времени (NTP)
Разница во времени между сервером и машинами ломает базы данных и логи. 
* **Настройка:** Перейди в **Manage -> System -> Time & date -> Edit**. 
* Выбери вариант **Use Network Time Protocol (NTP)**. 
* В строке NTP-серверов пропиши пул времени: `pool.ntp.org`.
* Перейди в **Actions -> NTP service -> Start and set to start with host** (чтобы служба времени запускалась сама при включении сервера).

### ⚖️ Фишка №2: Вся правда про Disk Provisioning 
При создании диска для VM есть три режима. Их нужно знать наизусть:
1. **Thin Provisioning (Тонкий):** Место на физическом диске выделяется по мере заполнения виртуалки. *Плюс:* Экономия места. *Минус:* Самая низкая скорость записи при первом заполнении.
2. **Thick Provisioning Lazy Zeroed (Толстый отложенный):** Сразу забирает всё выделенное место (например, 100 ГБ), но очищает его от старых данных только в момент записи. *Плюс:* Быстрое создание. *Минус:* Средняя производительность.
3. **Thick Provisioning Eager Zeroed (Толстый немедленный):** Сразу забирает все 100 ГБ и мгновенно забивает их нулями (полностью форматирует). *Плюс:* Максимальная скорость работы диска в будущем (идеально для тяжелых баз данных вроде PostgreSQL). *Минус:* Создается очень долго.

### ⚡ Фишка №3: Отключение тормозов процессора (Power Management)
По дефолту ESXi душит процессор ради экономии энергии.
* **Как исправить:** Перейди в **Manage -> Hardware -> Power Management -> Change policy** и переключи режим на **`High Performance`** (Максимальная производительность). Это заставит процессор всегда работать на полную мощность без микрозадержек при распределении ресурсов.
