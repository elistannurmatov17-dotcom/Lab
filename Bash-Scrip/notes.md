# Полный энциклопедический справочник по Bash-скриптам

Bash (Bourne Again SHell) — это командный язык и интерпретатор, золотой стандарт автоматизации и администрирования Linux-систем.

---

## 1. Фундаментальные правила и запуск

### Шебанг (Shebang)
Указывает системе, какой интерпретатор использовать. Должен быть строго первой строкой файла, без пробелов перед ним.
* `#!/bin/bash` — стандартный вызов Bash (рекомендуется).
* `#!/bin/sh` — запуск в режиме совместимости со старым POSIX-шеллом (многие фишки Bash там не работают).

### Права и запуск файла
```bash
chmod +x script.sh       # Делает файл исполняемым (права rwxr-xr-x)
./script.sh              # Запуск из текущей директории
sudo ./script.sh         # Запуск с правами суперпользователя root
```

### Проблема переноса строк (CRLF vs LF)
Если файл редактировался в Windows, он получит скрытые символы возврата каретки `\r`. При запуске в Linux это вызовет критическую ошибку `Bad interpreter` или `No such file or directory`.
* **Решение:** Выполнить команду `dos2unix script.sh` перед запуском.

## 2. Все виды переменных

В Bash нет строгой типизации — всё по умолчанию обрабатывается как строки. 
⚠️ **Важно:** Вокруг знака равенства `=` при присвоении **не должно быть пробелов**.

### Объявление и вызов
```bash
NAME="Debian"            # Строковая переменная
VERSION=13               # Числовая переменная (обрабатывается как текст)
echo \$NAME               # Базовый вызов
echo "\${NAME}-server"    # Правильный вызов в фигурных скобках (для изоляции имени)
```

### Командная подстановка (Запись вывода команды в переменную)
```bash
CURRENT_USER=\$(whoami)   # Современный и рекомендуемый способ
CURRENT_DIR=`pwd`        # Устаревший способ через обратные кавычки
```

### Переменные окружения и области видимости
Переменные внутри скрипта живут только пока скрипт работает. Чтобы передать переменную дочерним процессам, используется `export`.
```bash
export API_KEY="secret_123"
```

### Специфические встроенные переменные Bash
* `$0` — Имя самого скрипта.
* `$1`, `$2` ... `$9` — Позиционные аргументы, переданные скрипту при запуске (например: `./script.sh arg1 arg2`).
* `$#` — Количество переданных аргументов.
* `$@` — Все переданные аргументы одной строкой.
* `$LATEST` или `$$` — PID (идентификатор процесса) текущего скрипта.
* `$?` — Код возврата последней выполненной команды. **0** — успешно, **не 0** — произошла ошибка.

## 3. Массивы (Arrays)

Bash поддерживает одномерные индексированные и ассоциативные массивы.

### Индексированные массивы (списки)
```bash
PACKAGES=(ufw curl git htop) # Создание массива
echo \${PACKAGES[0]}          # Выведет первый элемент: ufw
echo \${PACKAGES[@]}          # Выведет все элементы через пробел
echo \${#PACKAGES[@]}         # Выведет количество элементов в массиве

PACKAGES+=(tmux)             # Добавление элемента в конец списка
```

### Ассоциативные массивы (словари / key-value)
Доступны, начиная с Bash 4. Требуют обязательного объявления через `declare -A`.
```bash
declare -A SERVERS
SERVERS[web]="117.0.0.0"
SERVERS[db]="0.0.0.0"

echo \${SERVERS[web]}         # Выведет: 117.1.0.0
```

## 4. Условия и логические проверки (if / case)

Проверки выполняются внутри скобок. Рекомендуется использовать двойные квадратные скобки `[[ ... ]]`, так как они безопаснее при работе с пустыми переменными и поддерживают регулярные выражения.

### Шаблон конструкции `if-elif-else`
```bash
if [[ \$VERSION -eq 13 ]]; then
    echo "Это актуальный релиз"
elif [[ \$VERSION -gt 13 ]]; then
    echo "Это тестовый или будущий релиз"
else
    echo "Старая версия системы"
fi
```

### Все флаги сравнения для условий

| Флаг | Значение (Для чисел) | Флаг | Значение (Для строк) |
| :--- | :--- | :--- | :--- |
| `-eq` | Равно (`==`) | `==` | Строки идентичны |
| `-ne` | Не равно (`!=`) | `!=` | Строки отличаются |
| `-gt` | Больше (`>`) | `-z` | Строка пустая |
| `-ge` | Больше или равно (`>=`) | `-n` | Строка НЕ пустая |
| `-lt` | Меньше (`<`) | | |
| `-le` | Меньше или равно (`<=`) | | |

### Флаги проверки файлов и папок
* `-f /path` — Объект существует и это обычный файл.
* `-d /path` — Объект существует и это директория (папка).
* `-e /path` — Объект просто существует (любого типа).
* `-x /path` — Файл существует и у него есть права на запуск.

### Объединение условий (Логика)
* `&&` — Логическое И (AND).
* `||` — Логическое ИЛИ (OR).
```bash
if [[ -d "/etc/ssh" && -f "/etc/ssh/sshd_config" ]]; then
    echo "Сервер SSH установлен и настроен."
fi
```

### Конструкция `case` (Аналог switch в других ЯП)
Идеально подходит для создания меню или обработки текстовых флагов запуска.
```bash
case "\$1" in
    start)
        echo "Запуск службы..."
        ;;
    stop)
        echo "Остановка службы..."
        ;;
    restart|reload)
        echo "Перезапуск..."
        ;;
    *)
        echo "Использование: \$0 {start|stop|restart}"
        exit 1
        ;;
esac
```

## 5. Циклы (Loops)

### Цикл `for` по списку элементов
```bash
for pkg in ufw curl git htop; do
    echo "Устанавливаю пакет: \$pkg"
    apt install -y \$pkg
done
```

### Цикл `for` по диапазону чисел
```bash
for i in {1..5}; do
    echo "Итерация номер \$i"
done
```

### Цикл `while` (Выполняется, пока условие ИСТИННО)
Часто используется для бесконечного ожидания или чтения файлов построчно.
```bash
COUNT=1
while [[ \$COUNT -le 3 ]]; do
    echo "Считаем: \$COUNT"
    ((COUNT++)) # Инкремент переменной
done
```

## 6. Функции (Functions)

Функции помогают избавляться от дублирования кода. Обязательно должны быть объявлены в скрипте **выше** места их вызова.

```bash
# Объявление функции
log_message() {
    # \$1 внутри функции — это первый переданный ей аргумент, а не аргумент скрипта!
    echo "[\$(date +'%Y-%m-%d %H:%M:%S')] : \$1"
}

# Вызов функции с передачей параметра
log_message "Скрипт начальной настройки запущен"
log_message "Все пакеты успешно установлены"
```

## 7. Перенаправление потоков и конвейеры

В Linux есть три стандартных потока данных:
* `0` (stdin) — стандартный ввод (клавиатура).
* `1` (stdout) — стандартный вывод (экран).
* `2` (stderr) — стандартный поток ошибок.

### Операторы перенаправления:
* `>` — Перезаписать файл выводом команды (предыдущие данные стираются).
* `>>` — Дописать вывод команды в конец файла (сохраняя старые данные).
* `2>` — Направить только ошибки в отдельный файл.
* `&>` — Направить и стандартный вывод, и ошибки в один файл.
* `/dev/null` — Черная дыра Linux. Если направить туда вывод (`> /dev/null 2>&1`), команда выполнится абсолютно бесшумно.

## 8. Арифметика в Bash

Поскольку по умолчанию всё является строками, для математических вычислений используется синтаксис двойных круглых скобок `(( ... ))` или утилита `expr`.

```bash
X=10
Y=5

(( SUM = X + Y ))       # Сложение
(( RESULT = X * Y ))    # Умножение
echo "Результат: \$SUM"

# Сокращенные операции
(( X++ ))               # Увеличение на 1
(( Y += 10 ))           # Прибавить 10 к текущему значению
```

## 9. Продвинутые фишки и перехват ошибок

### Безопасный режим Bash (Строгий режим)
Если вставить эти строки в самое начало скрипта (сразу под шебангом), скрипт мгновенно прекратит работу, если какая-то команда вернет ошибку или обнаружится пустая переменная. Это предотвращает порчу системы некорректным кодом.
```bash
set -e  # Выйти, если любая команда завершилась сбоем (не нулевым кодом)
set -u  # Выйти, если скрипт пытается использовать необъявленную переменную
set -o pipefail # Ловить ошибки внутри конвейеров команд через символ '|'
```

### Перехват сигналов (Trap)
Позволяет выполнить код очистки мусора, если пользователь прервал скрипт комбинацией **Ctrl + C**.
```bash
# Принудительно удалит временный файл при любом выходе из скрипта
cleanup() {
    rm -f /tmp/temp_file.txt
    echo "Временные файлы удалены. Выход."
}
trap cleanup EXIT
```

## 10. Дебаг и отладка (Как искать баги)

Никогда не гадайте, почему скрипт работает не так. Используйте режим трассировки:
```bash
bash -x ./autosetup.sh
```
*Система запустит скрипт и будет выводить каждую строчку кода на экран прямо в момент её выполнения, подставляя вместо названий переменных их реальные значения. Строки отладки визуально помечаются знаком `+`.*
