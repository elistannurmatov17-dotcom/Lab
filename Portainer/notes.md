# 🌐 Полное руководство по администрированию Docker через Portainer

**Portainer CE (Community Edition)** — это графическая панель управления (веб-интерфейс), которая превращает управление контейнерами через терминал в удобную визуальную работу в браузере.

---

### 1. Архитектура и скрытая логика: Как Portainer управляет Docker?

Portainer сам по себе является обычным изолированным Docker-контейнером. Чтобы он мог управлять другими контейнерами на сервере Ubuntu, применяется магия сквозного монтирования системного сокета.

* **Разбор манифеста в `compose.yaml`:**
  ```yaml
  services:
    my-admin-panel:
      image: portainer/portainer-ce:latest
      container_name: learning_portainer
      restart: unless-stopped
      ports:
        - "9000:9000"  # HTTP-порт для доступа из браузера
        - "9443:9443"  # HTTPS-порт (для защищенного соединения)
      volumes:
        - /var/run/docker.sock:/var/run/docker.sock # Главный пульт управления
        - portainer_data:/data                      # База данных самой панели

  volumes:
    portainer_data:
  ```

* **В чем логика строки `/var/run/docker.sock`?**
  Файл `docker.sock` — это Unix-сокет, через который Docker Engine принимает команды из терминала. Пробрасывая его внутрь Portainer, мы отдаем панели «ключи от сервера». Portainer перехватывает этот сокет и выводит всю системную информацию в веб-интерфейс.

---

### 2. Приколы первой настройки и Безопасность

В современных версиях Portainer (начиная с середины 2024 года) безопасность была сильно ужесточена, что вызывает путаницу у новичков.

#### Прикол №1: Окно «Setup Token»
При первом открытии страницы `http://<IP>:9000` панель не пустит тебя дальше, пока ты не введешь токен инициализации. Он генерируется автоматически при старте контейнера в целях защиты от перехвата админки роботами в интернете.
* **Где его взять:** Токен пишется строго в логи контейнера.
* **Команда для извлечения:** `sudo docker logs learning_portainer`
* **Что искать:** Строку, содержащую `setup_token=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`. Нужно скопировать только этот хэш (набор букв и цифр после знака `=`) и вставить в браузер.
* **Таймаут:** У тебя есть **5 минут** с момента запуска контейнера. Если не успел, токен сгорает, и панель заблокируется. Исправляется перезапуском: `sudo docker compose restart my-admin-panel`.

#### Прикол №2: Требования к паролю
Пароль администратора должен быть строгим — **не менее 12 символов**. В него обязательно должны входить латинские буквы и цифры.

#### Прикол №3: Подключение к локальной среде (Environment)
После создания пользователя выбери вариант **Get Started** (с иконкой кита Docker). Панель автоматически подцепит сокет хост-машины и создаст локальное окружение с именем `local`.

---

### 3. Главный функционал: Зачем Portainer нужен администратору?

После нажатия на окружение `local` ты попадаешь на главный **Dashboard** (Дашборд), который заменяет кучу терминальных команд.

#### Раздел `Containers` (Контейнеры)
Центральный пульт управления. Показывает таблицу всех контейнеров в системе, их внутренние IP-адреса (в подсети Docker) и проброшенные порты.
* **Быстрые действия (Quick Actions):**
  * 📄 **Logs (Иконка блокнота):** Заменяет команду `docker logs -f`. Выводит логи в реальном времени прямо на экран браузера. Можно включить автообновление (Auto-refresh logs) и автоперенос строк (Wrap lines).
  * 📊 **Stats (Иконка пульса):** Заменяет команду `docker stats`. Показывает живые интерактивные графики использования CPU (процессора), Memory (оперативной памяти) и сетевого трафика.
  * 🧰 **Console (Иконка `>_`):** Заменяет команду `sudo docker exec -it ... sh`. Позволяет провалиться в терминал контейнера прямо из вкладки браузера и выполнять там команды от root.
  * ℹ️ **Inspect (Иконка `(i)`):** Показывает подробнейший JSON-файл конфигурации контейнера (переменные окружения, пути, настройки сети).

#### Раздел `Images` (Образы)
Показывает все скачанные на жесткий диск «рецепты». Возле неиспользуемых образов горит синий ярлык `Unused`. Отсюда их можно удалять галочкой, чтобы очистить место на диске.

#### Раздел `Volumes` (Тома)
Список всех виртуальных флешек. Позволяет увидеть, какие тома созданы именованными (Named), а какие создались случайно (Anonymous) как мусор.

#### Раздел `App Templates` (Шаблоны приложений)
Встроенный маркетплейс. Позволяет развернуть популярные сервисы (WordPress, GitLab, Nextcloud, базы данных) в один клик без написания файлов конфигурации.

---

### 4. Шпаргалка админа по решению проблем (Troubleshooting)

* **Проблема:** Браузер пишет «Сайт не защищен» / «Соединение сброшено».
  * *Решение:* Portainer по умолчанию запускает веб-сервер на двух портах. Попробуй зайти по обычному HTTP через порт `9000` (`http://192.168.0.105:9000`). Если используешь защищенный порт `9443`, обязательно пиши протокол HTTPS в начале: `https://192.168.0.105:9443` (и игнорируй предупреждение браузера о самоподписанном сертификате).
* **Проблема:** На диске Ubuntu кончилось место (99% занято), Portainer вылетает.
  * *Решение:* Терминал — лучший друг админа в критической ситуации. Останови контейнеры и очисти мусорные слои образов и анонимных томов командой: `sudo docker system prune -a --volumes`.


# 🌐 Ультимативное руководство по всем вкладкам и фичам Portainer

Portainer делит управление сервером на логические вкладки в левом меню. Ниже подробно разобран функционал каждой важной зоны веб-интерфейса, который необходим системному администратору и DevOps-инженеру.

---

## 🏢 1. Вкладка Dashboard (Главная панель)
Это «пульт управления полетом». Он дает мгновенный снимок состояния твоего сервера.
* **Фича:** Все плитки (Containers, Images, Volumes, Networks) кликабельны. Вместо блуждания по меню можно сразу нажать на плитку, чтобы провалиться в нужный раздел.
* **Зачем админу:** Сюда заходят в первую очередь, чтобы проверить общую загрузку: сколько всего контейнеров запущено, сколько остановлено и нет ли «упавших» (Unhealthy).

---

## 🛠️ 2. Вкладка Stacks (Управление Docker Compose)
**Стек в Portainer — это и есть твой проект Docker Compose.** Панель автоматически объединяет контейнеры, запущенные из одного файла, в общую группу.
* **Главная фича (Редактор кода):** Ты можешь кликнуть на свой стек, перейти во вкладку **Editor** прямо в браузере и увидеть текст своего файла `compose.yaml`.
* **Изменение на лету:** Ты можешь отредактировать код (например, изменить порт Nginx или добавить новый сервис) прямо в текстовом поле браузера и нажать кнопку **Update the stack**. Portainer сам остановит старые контейнеры, применит новые правила и запустит всё заново. Терминал и `nano` больше не нужны!

---

## 📦 3. Вкладка Containers (Управление контейнерами)
Самая посещаемая вкладка. Здесь происходит ежедневная рутина админа.
* **Верхняя панель действий (Actions):** Галочками можно выбрать несколько контейнеров и в один клик отправить их в `Start` (Запуск), `Stop` (Остановка), `Kill` (Принудительное завершение) или `Restart` (Перезапуск).
* **Кнопка «Add container»:** Позволяет запустить любой новый контейнер вручную, заполнив форму (указать образ, пробросить порты и переменные окружения), вообще не создавая никаких yaml-файлов.
* **Продвинутая фича — Дублирование и Изменение (Duplicate/Edit):** Если кликнуть на имя конкретного контейнера, внутри будет кнопка *Duplicate/Edit*. Она позволяет «на лету» изменить настройки уже работающего контейнера (например, докинуть в него новую переменную окружения `ENV`) и пересоздать его одной кнопкой.

---

## 💿 4. Вкладка Images (Управление образами)
Здесь хранятся все скачанные «шаблоны/рецепты» программ.
* **Ярлыки состояния:**
  * `Unused` (Не используется) — образ лежит на диске, но из него сейчас не запущен ни один контейнер. Это главные кандидаты на удаление, если заканчивается место на сервере.
  * `Used` (Используется) — трогать нельзя, из него работает живой сервис.
* **Фича «Build a new image»:** Позволяет вставить текст файла `Dockerfile` прямо в браузер и собрать свой собственный кастомный образ.

---

## 💾 5. Вкладка Volumes (Управление дисками)
Список всех изолированных хранилищ.
* **Разделение типов:** Четко разделяет именованные тома (Named) от анонимных хэш-папок (Anonymous).
* **Фича «Браузер файлов» (доступна в некоторых версиях):** Позволяет зайти внутрь тома и посмотреть, какие файлы там лежат, не заходя на сервер по SSH.

---

## 🌐 6. Вкладка Networks (Управление сетями Docker)
Контейнеры изолированы друг от друга, если они не находятся в одной сети.
* **Типы сетей по умолчанию:**
  * `bridge` — стандартная общая сеть для одиночных контейнеров.
  * `host` — контейнер полностью убирает изоляцию и использует порты сервера напрямую.
  * `none` — контейнер полностью изолирован от интернета и других контейнеров.
* **Зачем сюда заходить:** Когда ты запускаешь Стек (`docker compose`), Portainer создает для него кастомную сеть (например, `docker-compose_default`). Кликнув на нее, ты увидишь список контейнеров и их **внутренние IP-адреса**, чтобы понимать, как они общаются между собой.

---

## 🖥️ 7. Вкладка Host (Информация о сервере)
Показывает состояние твоего «железа» (твоей виртуальной машины Ubuntu).
* **Что внутри:** Версия ядра Linux, количество ядер процессора, общий объем оперативной памяти и модель CPU.
* **Фича «Setup»:** Показывает настройки самого Docker Daemon (движка), включая пути к системным папкам.

---

## 🔐 8. Блок Administration (Администрирование панели)
Настройки для контроля доступа, если лабой пользуешься не ты один.
* **Users (Пользователи):** Можно создать аккаунты для друзей или коллег, выдав им права «только просмотр логов», чтобы они не могли случайно удалить твои базы данных.
* **Registries (Реестры):** Позволяет подключить к Portainer твой приватный аккаунт Docker Hub или GitLab Registry, чтобы скачивать закрытые коммерческие образы.
