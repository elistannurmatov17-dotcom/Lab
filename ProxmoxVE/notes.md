# 🌐 Домашняя лаборатория Proxmox VE на VMware Workstation


---

## 🛑 1. Управление сервером из Windows (VMware)
При закрытии окна VMware Workstation всегда выбирать правильный режим:
* **Run in Background** — Сервер продолжит работать «в фоне». Окно закроется, но Proxmox останется доступен в браузере.
* **Suspend** — Поставить сервер на «паузу» (состояние ОЗУ сохранится на диск). Использовать перед выключением ПК.
* **❌ Power Off** — Принудительное выключение. **НЕ ИСПОЛЬЗОВАТЬ**, это может повредить файлы и базы данных Proxmox.

## 🌍 2. Доступ к веб-панели и Сеть
* **Основной IP-адрес сервера:** `192.168.1.50`
* **Локальный домен хоста:** `https://homelab.local`
* **Сетевой режим в VMware:** `Bridged (Automatic)` — сервер работает как отдельный физический компьютер в домашней подсети роутера (`192.168.1.x`).

### 🔧 Настройка связки IP и Домена на Windows (Файл hosts):
Если в браузере возникает ошибка `DNS_PROBE_FINISHED_NXDOMAIN`, нужно связать IP с доменом:
1. Открыть Блокнот от имени администратора.
2. Открыть файл `C:\Windows\System32\drivers\etc\hosts` (переключить режим отображения на «Все файлы»).
3. В самый конец добавить строку:
   ```text
   192.168.1.50    homelab.local
   ```
4. Сохранить (`Ctrl + S`).

### 🔐 Авторизация в веб-интерфейсе:
* **Логин (User name):** `root`
* **Пароль:** *[Ваш секретный пароль, заданный при установке]*
* **Realm:** `Linux PAM standard authentication`
* **Язык (Language):** `Russian (Русский)`

## 🗂 3. Обзор основных вкладок и интерфейса

### Левая панель (Server View):
* **Datacenter (Датацентр):** Управление всей инфраструктурой, кластерами, бэкапами и общими правами доступа.
* **├─ homelab (Нода/Сервер):** Ваш конкретный виртуальный сервер. При клике на него открывается меню управления «железом» (процессор, сеть, диски, консоль Shell).
* **├── local (homelab):** Хранилище для ISO-образов, шаблонов контейнеров и бэкапов.
* **└── local-lvm (homelab):** Скоростное хранилище, предназначенное исключительно для виртуальных дисков самих создаваемых машин.

### Главные вкладки сервера (блок System):
* **Shell (Консоль):** Полноценный терминал командной строки Linux (Debian) для глубокого администрирования.
* **Network (Сеть):** Настройка сетевых мостов (vmbr).
* **Certificates (Сертификаты):** Управление SSL-ключами безопасности.
* **Repositories (Репозитории):** Источники, откуда сервер скачивает обновления компонентов.
* **Updates (Обновления):** Интерфейс для проверки и установки обновлений системы (кнопка *Refresh*).

## 🛠 4. Обязательная базовая настройка после установки

### 🔄 Перевод на бесплатные репозитории (No-Subscription):
По умолчанию Proxmox пытается обновиться с платной корпоративной базы, из-за чего возникает ошибка `apt-get update`.
1. Перейти в `homelab` -> `Repositories`.
2. Выделить строку `pve-enterprise` и нажать **Disable**.
3. Выделить строку `ceph enterprise...` и нажать **Disable**.
4. Нажать кнопку **Add**, закрыть предупреждение, в выпадающем списке выбрать **No-Subscription** и нажать **Add**.
5. Перейти во вкладку **Updates** выше и нажать 🔄 **Refresh**.

### ❌ Отключение баннера «No valid subscription» (Нет активной подписки):
Чтобы при каждом входе в панель не всплывало назойливое уведомление:
1. Открыть `homelab` -> **`>_ Shell`**.
2. Скопировать и вставить команду (вставка через `Shift + Insert` или правый клик):
   ```bash
   sed -Ezi.bak "s/(Ext.Msg.show\(\{\s+title: gettext\('No valid sub)/void\(\{\/\/\1/g" /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js && systemctl restart pveproxy.service
   ```
3. Нажать **Enter**. Консоль закроется со статусом `Connection closed` — это нормально (служба веб-панели перезапустилась).
4. Обновить страницу в браузере по кнопке **F5**.

## 💿 5. Подготовка к запуску виртуальных машин

### 📥 Загрузка ISO-образа ОС (Windows / Linux):
1. В левой панели выбрать хранилище **local (homelab)**.
2. В центре переключиться на вкладку **ISO Images** (ISO-образы).
3. Нажать кнопку 💾 **Upload** (Загрузить).
4. Нажать *Select File*, выбрать файл установщика системы (например, `.iso` образ Windows или Ubuntu) на вашем ПК и нажать **Upload**. Дождаться статуса `TASK OK`.

### 🚀 Пошаговое создание виртуальной машины (Кнопка "Create VM"):
В правом верхнем углу панели нажать синюю кнопку **Create VM** и заполнить вкладки мастера:
1. **General (Общие):** Указать понятное имя машины в поле *Name*.
2. **OS (ОС):** Выбрать пункт *Storage: local* и в списке *ISO Image* выбрать загруженный ранее установщик системы.
3. **System (Система):** Для Windows рекомендуется ставить галочку *Qemu Agent*. Для Linux можно оставить всё по умолчанию.
4. **Disks (Диск):** В поле *Storage* выбрать **local-lvm**. Задать размер диска (для тестов Linux хватает 20 ГБ, для Windows лучше от 40 ГБ).
5. **CPU (Процессор):** Указать количество ядер. *Важно:* в поле **Type** (Тип процессора) для лучшей производительности вложенных систем рекомендуется выбирать тип **host**.
6. **Memory (Память):** Выделить объем ОЗУ в мегабайтах (1024 МБ = 1 ГБ).
7. **Network (Сеть):** Оставить тип *Bridge* (`vmbr0`).
8. Нажать **Finish**.

### 💻 Запуск и управление машиной:
* Машина появится в левом списке под сервером `homelab` с уникальным ID (например, `100 (Имя)`).
* Нажать по ней правой кнопкой мыши -> **Start** (Запустить).
* Перейти во вкладку **Console** (Консоль) внутри этой машины — перед вами откроется экран созданного «компьютера», где начнется стандартная установка выбранной операционной системы.

## 💡 Разница между VM (Виртуальная машина) и CT (Контейнер LXC)
В верхнем меню Proxmox есть две кнопки: **Create VM** и **Create CT**.
* **VM (Виртуальная машина):** Полная эмуляция компьютера со своим независимым ядром ОС. Подходит для тяжелых систем (Windows, сложные сборки Linux). Требует много ресурсов.
* **CT (Контейнер LXC):** Сверхлегкая изолированная система, использующая ядро основного хоста Proxmox. Идеально подходит для запуска одиночных Linux-сервисов (Docker, базы данных, VPN, медиасерверы). Запускается за секунду и почти не потребляет ОЗУ.
